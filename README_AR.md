# حزمة نقل المحاكاة الرئيسية — IRTree–DIF (الشروط الثمانية الأساسية × 200 تكرار)

هذه الحزمة هي النسخة البرمجية المثبتة نفسها المستخدمة في التشغيل الجاري، دون أي تغيير في الخوارزميات أو البذور. والتكرارات المكتملة محفوظة فيها، فلا تُعاد عند الاستئناف.

## محتويات الحزمة

| المجلد أو الملف | المحتوى |
|---|---|
| `sim/` | الكود المثبت: main_sim.R وsim_core.R و02b_latent_fast.R وirtree_dif_sim.R و04g_confirmatory_paired.R، مع collect.R (التجميع والتحليل) وverify_install.R وverify_generation.R |
| `sim/conditions_56.csv`، `sim/conditions_core8.csv` | جداول الشروط |

## المتطلبات على خادم Linux

- إصدار R بالضبط **4.3.3**، لأن البرنامج يتحقق من الإصدار ويرفض غيره.
- أدوات البناء: `build-essential gfortran libblas-dev liblapack-dev libuv1-dev`.

في Ubuntu أو Debian تُثبّت بالأمر:
```bash
sudo apt-get install -y build-essential gfortran libblas-dev liblapack-dev libuv1-dev
```

لا يحتاج التثبيت إلى الإنترنت، لأن مصادر الحزم كلها داخل الحزمة. وبعد التحقق من سلامة الملفات يُثبَّت الكود هكذا:
```bash
sha256sum -c SHA256SUMS.txt            # التحقق من سلامة الملفات بعد النقل
Rscript R_env/install_pinned.R ~/Rlib_irtree     # 20–40 دقيقة أول مرة
```

## التحقق قبل التشغيل (إلزامي على أي جهاز جديد)

```bash
cd sim
export R_LIBS_USER=~/Rlib_irtree
IRTREE_COND=C047 IRTREE_REP_FROM=1 IRTREE_REP_TO=1 IRTREE_SEED_SCHEME=legacy IRTREE_ORACLE_DRAWS=3 IRTREE_OUT=check Rscript main_sim.R
Rscript verify_install.R      # يجب أن تظهر PASS
```

يعيد هذا الأمر تكرار المرحلة 4H، ويقارنه بالتكرار المرجعي، ويستغرق نحو 10 دقائق. وإذا لم تظهر PASS فلا تبدأ التشغيل.

## التشغيل والاستئناف على خادم Linux

```bash
cp -r results_core8_backup sim/results_core8     # مرة واحدة: البدء من التكرارات المكتملة
R_PINNED_LIB=~/Rlib_irtree bash scripts/run_linux.sh core8 1 200 $(nproc)
```

- **الاستئناف:** أعد الأمر نفسه بعد أي انقطاع. يتجاوز البرنامج كل تكرار محفوظ، ولا يترك ملفًا ناقصًا لأن الحفظ ذري (يُكتب الملف في ملف مؤقت ثم يُعاد تسميته دفعة واحدة).
- **أكثر من جهاز:** أضف إلى الأمر `SHARD=1 NSHARDS=2` على الجهاز الأول، و`SHARD=2 NSHARDS=2` على الثاني، بالعدد نفسه من العمليات، ثم اجمع المجلدات. ولا ضرر من التكرار المزدوج، لأن التكرار نفسه يعطي النتائج نفسها.
- **الإيقاف المنظم قبل مهلة محددة:** أضف `TIME_BUDGET_MIN=320`، فيتوقف التشغيل بين تكرارين قبل نفاد المهلة.
- **مكان النتائج:** `sim/results_core8/<الشرط>/rep_XXXX.rds`، ملف لكل تكرار.
- **التجميع والتحليل:**
  ```bash
  cd sim && Rscript collect.R results_core8 summary_core8
  ```

## التشغيل على GitHub Actions

1. أنشئ مستودعًا جديدًا، وانسخ إليه محتوى الحزمة كما هو (بما فيه `.github/`)، وادفعه إلى الفرع `main`.
2. شغّل مرة واحدة `bash scripts/seed_results_branch.sh`، فتُرفع التكرارات المكتملة إلى الفرع `results`.
3. من تبويب Actions اختر "IRTree core8"، ثم Run workflow.

**ما يفعله التشغيل:**

- **مهمة تجهيز:** تثبت R 4.3.3 والحزم المثبتة، وتتحقق من التكرار المرجعي (PASS) في أول مرة، وتحفظ مكتبة الحزم في الذاكرة المؤقتة للمستودع.
- **16 مهمة متوازية:** كل منها تستأنف من الفرع `results`، وتعمل حتى 320 دقيقة، ثم تضيف التكرارات الجديدة إلى الفرع `results` وتحفظ نسخة منها في Artifacts (ملفات التشغيل المحفوظة).
- **الاستمرار التلقائي:** يعيد الجدول الزمني التشغيل كل 6 ساعات حتى تكتمل التكرارات الـ1600، ثم تتوقف المهام تلقائيًا.

**تنبيهات:**

- **المستودع العام:** دقائق التشغيل فيه مجانية، والجهاز عادة 4 معالجات، فيُتوقع الانتهاء في نحو 3–4 ساعات.
- **المستودع الخاص:** المجاني فيه 2000 دقيقة شهريًا، ولا تكفي لهذا التشغيل (نحو 6000–7000 دقيقة)، فيلزم اشتراك مدفوع أو مستودع عام.
- **إذن الكتابة:** يحتاج التشغيل إذن الكتابة للفرع، وهو معرّف في الملف (`permissions: contents: write`). إذا رُفض الدفع فافتح Settings ثم Actions ثم Workflow permissions، واختر Read and write.

## ما يخص بيئة Claude فقط (لا يُستخدم على الخادم)

## ملاحظات على التطابق

- الكود والبذور وإصدارات R والحزم مثبتة. والبرنامج يتحقق من ذلك قبل كل تشغيل، ويختم كل تكرار برمز النسخة (manifest_id = ab03dffdf580).
- **مكتبة الجبر الخطي (BLAS):** المستخدمة هنا هي المكتبة المرجعية. وقد يغير استخدام مكتبة أخرى (مثل OpenBLAS أو MKL) قيم p في الخانات العشرية البعيدة (نحو 10⁻¹²). لذلك يُفضل تثبيت المكتبة المرجعية (libblas-dev)، ويبقى الحكم النهائي لاختبار verify_install.R.
- **التشغيل في مكانين:** إذا استمر التشغيل في جلسة Claude وعلى GitHub في الوقت نفسه، فقد يُحسب التكرار نفسه مرتين بنتيجة واحدة، ويُحتفظ عند الدمج بنسخة واحدة. ويُفضّل إيقاف أحد التشغيلين بعد التأكد من عمل الآخر.
